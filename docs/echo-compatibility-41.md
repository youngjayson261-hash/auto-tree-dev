# ECHO compatibility adapters: existing tree capabilities

This change extends the confidence-budget and bounded prefix FULL paths. It
reuses the existing tree builder, request state, budget transport, attention
metadata and graph managers. It does not enable random sampling, changing
draft depth, concurrent batches, asynchronous scheduling, PP, DP, PCP or DCP.

## Scorers and vocabulary contracts

| Scorer | Base | Scorer | Token IDs |
| --- | --- | --- | --- |
| Independent | Existing full-vocabulary path | Existing full-vocabulary path | Identity full vocabulary |
| DOMINO | Existing base path | Existing protected prefix and Top-C correction | Existing global vocabulary proof |
| Markov | Full draft-vocabulary distribution | Full corrected draft-vocabulary distribution | Validated injective draft-to-target map |
| DFlash2 | Rejected | Candidate-lattice distribution | Global target TopK IDs |

Markov candidates retain both raw draft-column IDs and global target IDs.
Base confidence gathers the former; the tree and target verification keep
using the latter. The checkpoint map is checked once after loading for
integer offsets, range and injectivity. Duplicate target IDs are rejected:
this change does not define probability merging for many-to-one maps.

DFlash2 supplies candidate logits rather than complete base logits. Its
Scorer normalization remains over that candidate lattice. Admission checks
the selector's codebook vocabulary and candidate interface; it must not
claim full-base probability semantics.

The factory selects `DFlash2BeamTreeBuilder`, which retains every parent's
top-k children in a pool wider than the next frontier. Confidence summarizes
the full normalized lattice and records paths for every retained pool child,
including forced origin children. It does not renormalize the shortlist or
change the beam's selection, pool order or final tree layout.

Confidence admission permits positive integer TP sizes and retains the
existing full-vocabulary model/scorer checks. Runtime sampling constraints
still apply. Fine-grained TP overrides and other parallel dimensions retain
their previous restrictions. A successful TP2 test is not evidence for every
TP topology or every checkpoint.

## Bounded prefix FULL graph grid

Supported target admission remains Qwen3. Eligible draft paths include
Qwen3DSpark/Markov, plain DFlash/Independent, shift-label DOMINO, and DFlash2
with Scorer confidence. Each adapter must also satisfy its vocabulary proof.
This is an admission boundary, not an assertion that all combinations have
completed model-level acceptance.

DOMINO prefix FULL retains its Scorer-only boundary. Base remains eager:
controlled Base FULL comparisons did not establish model-level AR agreement.

Capture keys contain real request count `R` and per-request capacity `G`.
Capture sizes are distinct integer capacities in `[1, budget+1]`; the root
and full-tree endpoints are added automatically. The previous nine-size
limit is removed. `max_num_batched_tokens` must fit
`max_num_seqs * (budget+1)`. Graph count grows with both dimensions.

For actual lengths `[13,2]` and gears `[1,5,9,13,17]`, select `(R=2,G=13)`
with 26 physical rows. Selecting only by the real total 15 or by its average
would use the wrong per-request geometry. Equal total sizes such as `(1,3)`
and `(3,1)` retain separate descriptors. Prefill and mixed batches run eagerly;
decode dispatch rejects a missing descriptor rather than fabricating requests.

Ragged target queries remain packed TND in the runner. Attention transfers
them to persistent BSND buffers, invokes FIA with real per-request lengths,
then restores TND order and zeros the physical tail. Transfers read the
existing device `query_start_loc_gpu`; positions and KV slot assignments do
not change. Fixed-grid kernels are needed because the supported CANN task
groups reject the device memcpy generated by ordinary `copy_` transfers.

Synchronous scheduling, one concurrent batch, greedy sampling, no LoRA/KV
transfer/adaptive verification, and PP/DP/PCP/DCP=1 remain required. Draft
capture initializes its existing manager with all real request-count gears,
independently of per-request target capacities, then restores the config.

## Wide mixed-state tree verification

The existing GDN recurrent operator accumulates per-request token counts into
tight offsets. Wide-tree chunk plans now pack all live request prefixes before
trailing padding while retaining fixed capacity and original parent/state IDs.
Per-request padding between live prefixes would make a short final chunk read
another request's unused cell. This changes tree transport only, not the
recurrent equation or the native operator; GDN prefix FULL is not enabled.

Padded tree KV gather/scatter also unwrap constant tuples before subscripting
on Triton 3.2. Addressing, invalid-index behavior and page strides are unchanged;
this conversion occurs at compilation rather than adding per-step device work.

## Validation boundaries

### Optional eager physical capacity for hybrid targets

`verification_eager_pad_to_full_tree` defaults to false. When explicitly
enabled, an eager Qwen hybrid target with DFlash2 Scorer confidence uses
`real_requests * (budget + 1)` physical rows for tree verification. Prefill
and root-only batches keep their ordinary shapes. This reuses the runner's
batch descriptor and padding buffers; it does not add requests or publish
extra candidates. Each request's attention and GDN lengths remain real.

The option addresses BF16 output sensitivity when pruning changes matrix
execution shapes: a hybrid single-request comparison flipped a tied argmax,
while a full-capacity diagnostic retained the AR output. GDN does not admit
the framework's batch-invariant mode. Keeping the physical shape is a
conservative compatibility choice, not a general bitwise-reproducibility
guarantee for all checkpoints.

Both target and draft must enforce eager execution. Capacity must satisfy
`max_num_batched_tokens >= max_num_seqs * (budget + 1)`. The option requires
enabled Scorer confidence and an admitted Qwen hybrid/DFlash2 combination;
it does not enable hybrid prefix FULL. Padded transformer rows still incur
computation, so reduced live candidate counts do not establish a speedup.

```json
{"tree_spec_config": {"enabled": true, "budget": 16, "topk": 4,
  "verification_policy": "confidence", "verification_threshold": 0.1,
  "verification_confidence_source": "scorer_logprob",
  "verification_eager_pad_to_full_tree": true}}
```

CPU tests cover policy/runtime admission, mapped Markov Base/Scorer scores,
DFlash2 candidate semantics, unchanged tree layout, real-R graph descriptors,
ragged metadata, endpoint insertion, more than nine sizes, and invalid inputs.
The native multi-request test checks full-cache padding sentinels plus ragged
FIA eager/replay equality across request reorder and capacity transitions.

```bash
python -B -m pytest tests/ut/spec_decode/test_tree_confidence_adapters.py \
  tests/ut/spec_decode/test_tree_eager_capacity.py \
  tests/ut/worker/a2/test_tree_prefix_graph.py

# Use one explicitly reserved visible NPU.
ECHO_TEST_NPU=1 python -B tests/ut/worker/a2/test_tree_prefix_batch_native.py
```

Component equality does not establish model-level AR equivalence or a speedup.
Full-model comparisons must record request submission/batching, exact input
tokens, sampling, source contents, TP/BS, execution mode, actual capture/replay
and budget cohorts. Different first-prefill batch shapes are not a controlled
eager/FULL pair. Historical output differences in the
[prefix graph guide](echo-prefix-fullgraph.md) remain historical evidence;
this change does not retroactively close those acceptance records.
